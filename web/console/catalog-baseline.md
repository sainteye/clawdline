# Console catalog baseline

`public/catalogs/baseline-keys.json` records the keys present in the first complete nine-language release. Its `version` starts at 1. After that release, add new English and `zh-Hant` copy in the same code change. Other languages may omit those new keys until a catch-up; the validator reports their missing count and runtime fills each gap from English while retaining the selected document language.

The source extraction is reproducible from the repository root with `node web/console/tools/compose-catalogs.mjs` (without `--write`); it prints `{"english":3389,"chinese":3389,"added":909}` for its historical source snapshot. The pinned Projects renderer also needs 10 Project and 54 worktree adapter keys. Thirteen complete numeric sentence templates replace 19 brittle JSX fragments; the applied skill receipt replaces one more JSX fragment with `template.squadSkillUseReceipt` so Session and skill names have language-specific order. Four Board modal eyebrows found in the real browser are translated. Twenty-three complete Documents page keys cover the active copied renderer through an editable bridge. The daemon Feature commit `690229e0dc7f846a6adbd713f68f456f3a978b56` supplies 1,192 fixed HTTP refusal keys in each of its nine `internal/productcopy/http_refusals/<tag>.json` files; its review manifest is `http-qa-coverage.json` (SHA-256 `a3ac3d6e12c53653f2c19335d578ce4f989dad0fcb510e8fd7f6bf1aafec66b2`). The importer checks the nine source key sets and validates the complete merged catalogs before writing. It changes command-example angle brackets to safe Unicode brackets for ten explicit display keys, while preserving wire strings and stable key hashes. The checked-in v1 `baseline-keys.json` has **4,604 keys**, including `lang` and `dir` (4,602 content keys). `catalog-inventory.json` classifies the full count. The checked-in catalogs, not the source-extraction helper, are the release artifacts. Run `node web/console/tools/validate-catalog.mjs --reference web/console/public/catalogs/en.json --target web/console/public/catalogs/<tag>.json --tag <tag> --initial` for each initial-release language.

Before this initial release, a corrected sentence may replace its unused fragment keys in all nine catalogs and in baseline v1 in one change. The 13 count templates above were reviewed with 0, 1 and many values and with a long source label. After the initial release, use the deletion and versioning process below.

When removing a baseline key, remove it from English and every translated catalog in the same change, remove it from `baseline-keys.json`, and increment `version`. A key left in any translated catalog is invalid because runtime rejects keys absent from English. Review the changed key set with the strict nine-language `--initial` validator before releasing that deletion. Do not add new keys to the baseline during routine copy changes; a later explicit rebaseline may add them after every language has been completed and checked.
