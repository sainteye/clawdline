# Task-focused technical documentation

Use this skill when writing or restructuring product and engineering documentation. Identify the reader's task first: learning a concept, following a procedure, looking up a reference, or understanding a decision.

1. Read the current implementation and relevant decisions before describing behavior. Cite the exact file, command, or observed response for claims that might have changed.
2. Give each page one clear purpose. Put prerequisites before actions; show commands that a reader can actually run; state expected output and failure recovery.
3. Separate a step-by-step guide from reference material and explanation when mixing them would obscure the task.
4. Check links, examples, terminology, and privacy. Follow this repository's English documentation and commit-message rules.

Do not manufacture implementation details or demand a new approval step when the user's authorization already covers the work.
