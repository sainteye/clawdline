# Accessibility review and fixes

Use this skill when building or reviewing web UI code for keyboard and focus behaviour, ARIA, accessible names, forms, announcements, motion and zoom against WCAG 2.2 A and AA; not for legal compliance claims or colour design.

Review with two walks: keyboard only, where every flow completes without a mouse; then screen reader, where every control announces a name, role and state. Prefer the platform default to a custom rebuild, and remove ARIA rather than add it. A finding cites a WCAG 2.2 A or AA criterion by number, or a task an assistive-technology user cannot complete; anything else (AAA, conventions, larger target sizes) is a recommendation and never `HIGH`.

- **Native first.** `<button>` for actions, `<a href>` for navigation (with Cmd/Ctrl and middle-click working), never a clickable `<div>`. Native `disabled` for unavailable controls; `aria-disabled="true"` only when it must stay focusable, with its behaviour blocked in code.
- **Focus.** Style `:focus-visible`; never remove the outline without a verified replacement reaching 3:1 against adjacent colours (1.4.11); keep forced-colours mode working. A focused element is never fully hidden under sticky chrome (2.4.11).
- **Keyboard.** Every pointer interaction has a keyboard path, following the ARIA authoring patterns: Escape closes overlays, arrows move within composite widgets, Tab moves between widgets, Enter and Space activate. Only `tabindex` 0 and -1; roving tabindex inside composites, `aria-activedescendant` where focus stays in an input.
- **Dialogs and routes.** Prefer `<dialog>` with `showModal()`; otherwise make the background `inert`, use `role="dialog"` and `aria-modal="true"`. Move focus in on open and back to the trigger on close. After a client-side route change, update `document.title` and move focus to the new view's heading or `<main>`.
- **Targets.** At least 24×24 CSS pixels or a listed exception (2.5.8); aim for 44 on touch and 40 on desktop where density allows, expanding with a pseudo-element. Hit areas never overlap; decorative layers take `pointer-events: none`. Every drag has a single-pointer alternative (2.5.7).
- **Forms.** Every input has a real label, never only a placeholder; label and control share one target. Valid `autocomplete`, a descriptive `name`, the right `type` and `inputmode`. Never block paste. Validate on submit rather than disabling submit; mark failures `aria-invalid="true"`, point `aria-describedby` at the inline error and focus the first invalid field.
- **Names and images.** Icon-only buttons get a descriptive name that includes any visible label text. Decorative elements are `aria-hidden="true"`, never on something focusable. Alt text: empty for decoration, meaning for information, the action for a functional image.
- **Colour and contrast.** Status has a second cue besides colour (1.4.1). Text needs 4.5:1, large text 3:1, component boundaries and meaningful graphics 3:1. Report a failing pair and the criterion; leave the colours alone unless asked.
- **Motion and time.** Motion is opt-in under `prefers-reduced-motion: no-preference`; reduced motion swaps slides for fades and stops parallax and autoplay. Anything moving or updating on its own for more than 5 seconds has a pause (2.2.2); toasts with an action or error stay until dismissed.
- **Announcements.** `aria-describedby` for field errors; a polite `role="status"` region, rendered empty before its text changes, for non-urgent updates; `role="alert"` only for urgent errors.
- **Structure and zoom.** Descriptive headings, one `<main>`, a skip link when repeated chrome precedes it. Text survives 200% (1.4.4) and the page reflows at 320px without horizontal scrolling (1.4.10). Never `maximum-scale=1` or `user-scalable=no`.

**Report.** `HIGH` prevents a task, hides content from assistive technology or is systemic; a missing name, missing focus indicator, pointer-only path, ignored reduced motion, loss at 320px or 200%, or colour-only meaning is `HIGH` on sight. `MEDIUM` makes an interaction meaningfully harder; `LOW` is polish. One row per root cause with location, before, after and the criterion. Without a browser, check names, handlers, focus styles, motion guards and label bindings in source; with one, tab through in order, read the accessibility tree, and run an automated audit as a source of candidates to confirm by hand. Mark checks not run as not verified, and do not substitute this review for testing with disabled people.
