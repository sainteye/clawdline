# Clawdline 2.7.0

Use Claude Code Remote Control from the console, share public community discussions deliberately, and inspect how your machine and Cloud services respond.

- **Use Remote Control conversations here.** On macOS and Linux, externally discovered native Claude Code Remote Control workers appear with a Remote Control marker and readable conversation history, including quota failures when no local transcript exists. Send text and images, inspect a pending tool request and allow it once or deny it, interrupt the worker, or close that specific worker. Permission answers bind to the live request and complete tool input; closing preserves unfinished-work checks and confirms worker exit. The integration uses the current Claude Code sign-in through an undocumented controller interface and can become unavailable when that interface changes. General file attachments, permanent approvals and structured question answers still use Claude. Native tests verified image delivery followed by quota refusal, idle interruption and worker exit; successful image inference, real tool-permission execution and active-turn interruption were not verified.
- **Choose what becomes public.** Community discussions separate questions, Issues and Ideas, support public replies, and explain which identity and original discussion details will be shared before publication. Private support questions remain private unless explicitly published. Community links include public sharing previews and readable source names; search and filters expand when needed, retain a usable desktop width, and use simple navigation tabs.
- **Read performance with the right context.** Paired owners can inspect their machine's API counts, latency and response history from Cloud. Administrators have separate Cloud service views. Changing the selected identity clears previous readings, and intentional long-poll waiting is identified separately from ordinary response time. Local history preserves unrelated files and records data loss before publishing counts. Capacity warnings distinguish pressure from expected recycling and quiet successful log rotation.
- **Find more of your existing work.** Project history includes Codex conversations started in the IDE. Older Cloud messages retain their negotiated reply identity. Project usage rows show configured Project icons, and machine monitoring keeps the selected machine visible across views.
- **Keep pictures in the current editor.** Unsent pictures no longer open or persist in IndexedDB; they remain available in the current composer and must be selected again after reload or leaving that editor. Text drafts continue using their existing per-Session persistence. Background Project discovery avoids unchosen personal folders, and protected-path access is requested when a saved Project is selected.
- **Follow support and planning more clearly.** Support threads show connected GitHub pictures and the newest reply, distinguish feature requests, and retain unfinished classifications during refresh. Answered questions use a quiet check. Accepting a proposal reveals its new Plan in the desktop Board.
- **Close overlays consistently.** Escape consumes the browser's default action when closing dialogs, the new-Session sheet or the input state. Update notices remain vertically centered. Shared images use the correct language, and the README explains the Project workflow.

English and Taiwan Traditional Chinese include the new product copy. Other supported languages keep the existing English fallback for newer untranslated text.
