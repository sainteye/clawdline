# Codync reuse and evidence boundary

Pinned upstream: `leepokai/Codync` at
`234219cef2d3f991f0f7225ba89e3c99cdd34177`. This foundation ports selected pure
rules to Go and defines their integration boundaries. It does not copy or run
the entire host, Electron shell, accounts, relay, cloud or background services.
The original Apache-2.0 LICENSE and NOTICE are preserved verbatim in
`third_party/codync`; its [DERIVATION.md](../third_party/codync/DERIVATION.md)
records modifications and distinguishes completed ports from later work.

The Go code was written as an adaptation of these rules, not generated by
translating Rust syntax or copied wholesale. Direct unchanged copies in this
commit are the upstream LICENSE/NOTICE only. Runtime/frontend source extraction
must extend derivation records with the actual paths/functions when delivered.

The six BR-v2 images were visually inspected for this foundation. They establish
the approved static target, not a functioning browser or Cloud acceptance.
N01 fixes the global entry at blob/#e39567 independently of every Bot. PA-04
uses the design's reviewed SVG `shape_path`; retaining a path's provenance is
preferable to importing upstream canvas/theme/cache machinery. The source-map
and voice hazards supplied by the root are incorporated in the handoff.

## Required provider evidence before admitting native mode

1. Resolve an explicitly installed executable; record exact CLI/adapter
   versions, protocol/capability fingerprint and provenance. Do not install via
   npx/registry fallback during a probe. Distinguish absent from uninspected.
2. Establish a supported authentication route in a feature-owned runtime
   directory without copying credentials or silently borrowing shared state.
3. Inspect effective system instructions, owned MCP list, model/mode and
   per-process memory settings. Reject a collision or inherited widening
   setting; prompt text and plan/manual modes do not enforce read-only access.
4. Prove native sandbox startup and a successful normally writable control,
   then deny file and shell writes, including canonical paths/symlinks/worktrees
   and separate tool processes. Native permission answers must not widen it.
5. Prove native automatic memory is disabled or isolated per Bot/Project and
   old histories/summaries cannot bypass forget revision fences. Test foreign
   Bot/Project sources and unchanged external settings/files separately.
6. Record scripted evidence separately from real provider/model behavior.
   Model prompts require a separately approved provider/request/cost cap.

Candidate controls from source inspection are not verified recipes: Claude's
explicit tool removal, owned settings/settings sources, disabled auto-memory
and auto-dream; Codex's installed-schema-supported read-only permission profile,
owned state and disabled `memories` feature. An isolated home does not by itself
retain login. Both require a proved process/tool boundary and owned MCP tools.

Pinned Codync's `host/src/agent/own_memory.rs` does not switch off Codex memory
and its test explicitly excludes Codex from switchable backends. Current
reported CLI evidence recognizes a `memories` feature. Porting that omission
unchanged would violate N02; the capability gate therefore remains closed.

Native failures use typed codes: cli_not_installed, adapter_not_found,
adapter_inventory_unknown, provider_version_unsupported, auth_required,
auth_probe_unknown, auth_rejected, auth_unavailable_in_isolated_runtime,
sandbox_unavailable, read_only_unverified, scope_expansion_denied,
memory_isolation_unverified, resume_forbidden_after_forget,
resume_unsupported and execution_effect_unknown. These are protocol values,
not claims that all corresponding real failure modes were exercised.

No usage-priced API or model request was made by PA-01: request count 0, cost 0.
No provider was installed, logged in/out, restarted or deployed. The root's
reported source probes remain attributed evidence; runtime and product
acceptance belong to PA-02/05 and the eventual authorized native tests.
