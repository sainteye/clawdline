Session 狀態篩選設計比較

Claude Code 使用官方 frontend-design 技能完成的三個方向。以下是實際畫面擷取的靜態圖稿，方便在 Cloud 與手機閱讀；圖中的按鈕不會操作你的 Session。

共同位置：吉祥物開側欄，「clawdline」文字開機器 Dashboard；原本「幾個在跑」的位置改成狀態篩選入口，清單上方的篩選列收起來。

A　勾選後套用（建議）

可複選。選好後按「顯示 N 個」才生效，取消不會改動清單；重新整理放在搜尋框旁。

B　點選立即生效

可複選。按一下就改變清單，按「完成」關閉；重新整理放在視窗頂端。

C　一次選一種狀態

單選，選好立即關閉。操作最精簡；重新整理放在視窗底部。

我的建議

選 A：保留頂列的狀態資訊，支援複選，而且可以先看結果數量再套用。重新整理保持在搜尋旁，少一次開視窗的操作。

實作前一起確認的五項

  1. 方向：A、B 或 C。建議 A。
  2. 複選：符合任一勾選狀態就顯示；「全部顯示」清除篩選。建議支援複選。
  3. 是否增加「狀態未更新」：圖稿有畫出來，目前產品尚未有這個選項。建議保留明確的「全部顯示」，避免漏掉不屬於已選分類的 Session。
  4. 單台與所有機器：是否都套用這個入口。建議都支援；「需要注意」包含等你回覆及待處理事項，實作時依各畫面的實際資料核對。
  5. 是否記住篩選：建議本次開啟期間保留，重新載入後恢復全部，避免下次誤以為 Session 不見了。

你可以先選 A／B／C，再直接用編號補充要改的細項；目前沒有實作篩選功能。
