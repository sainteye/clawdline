## 第一次檢視時間

在 **2026-11-06（臺灣時間）當天或之後的第一個適用任務**檢視；若已取得五次適用任務
的收據，可提前。這是任務觸發條件，不是背景排程，也不代表當天零時會自動跑評估。
使用者照常提出需求即可。

檢視前先讀 Project 記憶 `workflow-skill-pilot`；若已記錄這些技能版本的檢視完成，就不
重複執行。檢視後更新同一筆記憶，保留前輪紀錄，寫下日期、輸入版本、證據界線與
結果（包含證據不足）。只放摘要與證據位置，不放私人對話正文。

檢視已授權且身分明確的任務紀錄，保留技能讀取、實際影響的決策、驗證結果、不必要的
提問、可量測的額外工具／模型成本與退步案例；不搜尋無關私人歷史。清單出現技能或
Agent 自稱用過，都弱於實際讀取與工作證據。五個不同任務只能作觀察，不能冒充對照
實驗。若沒有適用任務，就記為「證據不足」，不自動延長試行或啟動付費呼叫。

要推廣到內建角色、全域預設或其他專案前，需完成受控比較並審查效益與負擔；保留
負面結果。若技能沒有價值，也可以建議移除。

## 現在可執行的離線準備

評估工具僅使用 Python 標準函式庫，不執行助理或網路呼叫。六種合成情境涵蓋重新連線
傳送、錯誤審查前提、正式資產過舊、child 未落地、小改字，以及綠燈測試漏掉重啟需求。

```sh
python3 tools/workflow-eval.py prepare --out /tmp/workflow-pilot-trial \
  --model 'exact model version; effort; harness; permissions' --repeats 5
python3 tools/workflow-eval.py report /tmp/workflow-pilot-trial
```

輸出需放在所有 Git 儲存庫之外、尚不存在的目錄。預設五次重複，共產生 60 份提示
（六情境 × 兩組 × 五次）。執行前須將 model 標籤換成真實、固定的模型版本、推理強度、
執行環境與權限。較少樣本只能檢查工具，無法取得 `repeated_sample_ready`。

對照組保留既有儲存庫指示，候選組只增加新技能清單與固定內容的檔案位置；由 Agent
自行判斷是否讀取。兩組都不提供評分標準或預期答案。每個樣本使用獨立新上下文與
相同模型／版本、推理強度、工具及權限，不繼承對話或外部技能清單。執行者只取得該份
提示及 `sources/` 的存取權；對照組不得在已探索到試行技能的 checkout 內執行。
這驗證所提供技能清單下的探索／使用，不代替原生 CLI 探索驗收；偏離實驗流程的部分
需隨結果揭露。

準備提示不代表核准模型費用。真正執行前依當時付費 API 規則，確認供應商／SKU、
估計金額、呼叫或費用上限、禁止自動重試，並在需要時取得明確核准。工具沒有自動
執行器或付費備援。可先免費檢視既有任務證據，但須保留觀察性資料的限制。

## 回覆與評分

1. 將完整原始回覆存於儲存庫外的 `responses/<trial-id>.txt`；另保留實際用量／費用收據。
2. 獨立評分者只取得固定的 `rubric.json`、`grading.json` 的情境編號及回覆，不看
   `manifest.json` 或提示，以盡量遮蔽分組。依行為判斷，不以關鍵字計分。產生回覆者
   不自行評自己的樣本；若回覆本身洩露分組，也需註明。
3. 填入評分者、精確 model 標籤、原始回覆檔案的 `response_sha256`。每項標準填布林值
   `passed`、回覆中的逐字引文 `evidence`，以及理由 `reason`。引文只證明可追溯性；
   意義及缺漏仍需人判斷。
4. 執行 `report`。exit 0 表示準備成功或評分資料完整，不表示有效；exit 2 表示尚未
   執行／資料不全，不輸出兩組比較；exit 1 表示資料無效、變動或無法讀取。

雜湊固定 manifest、來源、提示與評分標準，可抓意外漂移，不能防止有權限的人連資料
與雜湊一起重寫。回覆更動會使舊評分失效。所有規劃樣本必須齊全、配對且使用相同
設定，才輸出比較；逐情境結果會保留，避免總分掩蓋退步。工具不會自動決定採用。
即使每組五次，也只是這些案例的描述性證據，不是普遍提升品質或生產力的統計證明。

## 本輪證據界線

本地測試驗證漏樣本、重複樣本、證據變動、虛構引文、模型不一致、來源漂移、逐情境
退步與路徑界線，也核對兩個探索目錄都指向正式技能。這些只驗證工具與設定契約，
不是 LLM 實驗。本輪尚未收集對照／候選組回覆；行為成效、原生選用率、token 成本與
節省時間仍未知。

2026-10-30 使用 Codex CLI 0.162.1、隔離的暫存 `CODEX_HOME` 與本工作樹執行
`skills/list`（`forceReload: true`），兩個技能皆列為啟用，專案技能錯誤為空。
只送出 `initialize`、`initialized` 與 `skills/list`，沒有建立 thread 或啟動模型回合。
這證明該環境的 Codex 原生探索成功，不代表選用或遵循；Claude 仍只核對相對連結。
介面與位置依據 [skills/list 官方文件](https://learn.chatgpt.com/docs/app-server)及
[專案技能探索文件](https://learn.chatgpt.com/docs/build-skills)。

將工具暫改成「未執行也算已評分」時，空證據測試確實失敗；逐位元組還原後，19 項
本地測試全過。CLI 準備測試產生 60 份提示、零模型呼叫；報告正確回傳 exit 2、零已
評分樣本，且沒有兩組比較。這些是基礎設施結果，不是技能成效結果。
