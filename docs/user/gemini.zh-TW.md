# 使用 Gemini 個人預覽

[English](gemini.md)

Clawdline 介面將這個助理稱為 **Gemini**；目前預覽版透過所選機器上的
Antigravity ACP CLI 執行。Gemini CLI 與 Antigravity 是不同產品，安裝或登入其中一個，
不代表另一個也已可用。

機器擁有者啟用個人預覽後，已連線的使用者都能看到入口。預覽使用已登入的個人 Google
帳號，並維持 **AI Credits 關閉**。免費帳號仍有額度限制；額度用完時，Clawdline
不會自行切換到 API key 或付費備援。

## 開啟與傳訊

1. 在 Session 清單選擇機器，按 **開一個 session**。
2. 選擇 **Gemini**，再選專案。
3. 輸入訊息並按 **送出**。你的訊息會先出現，接著同一個原生回合的助理文字與工具狀態持續更新。

傳送被接受不代表模型已完成回覆。連線中斷時，先讀取對話與目前狀態，再決定是否傳送新訊息；
系統不會因為遺失確認就自動重送。

看不到 Gemini 時，先確認所選機器是否已啟用個人預覽。啟動回報登入問題時，請在該機器登入
Antigravity 所使用的個人設定，再重新開啟或續接。空白對話在你傳送訊息前不會有助理回覆。

## 閱讀歷史與續接

開啟原有 Session 即可閱讀已保存的對話。往上捲動，並在有入口時按 **載入更早的訊息**，
查看更早的訊息與工具結果。不同回合即使文字完全相同，仍會分開保留。

要回到過去的原生對話，請在建立視窗選 **接續之前的**，再於原專案選擇確切對話。
續接保留原身分，不會另建替代對話，也不會自行傳送新訊息。較早的原生歷史可能需要先載入。

服務重啟會停止原生程序，但保留已保存的對話。機器恢復在線後，續接原對話並明確傳送新訊息即可；
重啟時中斷的回合不會自動重做。只要擁有該對話的 daemon 在線，登入待處理時仍可讀取已保存的歷史。
離線機器無法向手機提供新的歷史讀數或接受新訊息。

## 回覆工具權限要求

原生 CLI 提出權限要求時，Session 會顯示問題與實際提供的選項。請針對畫面上的工具選擇；
核准範圍依原生選項標示，例如僅此一次或持續允許，Clawdline 不會把拒絕改成允許。

Clawdline 不會用 45 秒總時限中斷模型回合或等待你選擇權限。問題會保留到你回覆，
或原生回合／程序被取消為止；啟動、設定與管線寫入仍有短時間的逾時保護。

要求已改變或失效時，請重新整理對話並閱讀目前問題。關閉對話或取消都不會核准待處理工具。
唯讀裝置可以閱讀對話，但不能回覆權限要求。

原生工作區限制可能在出現權限選單前就拒絕工具。此時請閱讀工具失敗狀態與助理說明；
主控台沒有可以回覆的待核准要求。

## 模型、推理強度與額度

開啟 **關於這個 session** 查看原生模型選項；CLI 有另行提供時，也會顯示 **推理強度**。
模型與推理強度是分開的設定。較舊的原生回應若只提供模型變體，介面會保留為模型選項，
不自行推測成推理強度控制。

額度來自原生帳號讀數，有資料時會附觀察時間與重設時間。沒有資料代表未知，不能當作零用量。
Context 顯示目前上下文讀數，不是帳單或金額估算。

## 角色與共用專案記憶

機器回報支援角色時，可以在 **開一個 session** 選擇角色。daemon 會沿用其他助理使用的
原始角色、團隊手冊與已啟用技能快照，一併傳入共用專案記憶和所選語言。開啟空白對話
不會送出模型輸入；第一則訊息會將這些指示與你的原始文字分開傳送。

續接對話會保留原始快照，即使角色設定已改動，也不會改用新版本或重送中斷的訊息。
較舊且尚未支援這條路徑的機器會隱藏角色選項。

原生 CLI 目前會在歷史重播時將嵌入指示併入使用者文字。只有第一個重播回合與已保存的
上下文和原始輸入完全吻合時，Clawdline 才會還原原文；未知格式會保留，不猜測刪除文字。

原生工具會使用自身的 Clawdline 對話身分。CLI 派工可以透過既有角色小隊、工作樹、
簽收與交件流程啟動 Gemini 子代理。模型與權限選項必須經原生 CLI 確認。
子代理完成通知只有在該通知所屬回合正常結束後，才會記錄為已讀；取消或達到上限的回合
不會產生這張收據。

## 閱讀工具活動

讀取與搜尋活動會顯示原生提供的檔名和行號範圍。連續活動可以整組展開，每筆工具也能
展開收到的結果；大型結果只在展開時從已保存歷史讀取，收合不會刪除歷史。

委派卡片會顯示 Gemini 指定的角色。有明確原生子代理身分的活動會分組顯示；未提供身分
的活動不會猜測歸屬。委派呼叫已完成，不代表所有子代理都已完成。

部分原生介面版本會回傳空白文字結果，即使 CLI 自己的紀錄已有輸出。Clawdline 會將這種
情況與舊紀錄沒有保存結果分開顯示，也不會重新讀取來源檔案，將目前內容冒充為較早的工具
結果。工具完成狀態依原生通知更新，通知有時會晚於助理回覆抵達。

## 預覽範圍

目前預覽不提供原生終端附掛，
也不提供只取消當前回合的操作。此原生程序接線支援 macOS 與 Linux，尚未啟用 Windows。

連線問題請參考[恢復操作說明](recovery.md)；手機與其他機器的使用方式請參考
[Clawdline Cloud](cloud-first-look.md)。

## 自動命名

**設定 → 自動命名新 Session** 也適用於 Gemini。可在這裡選擇 Claude Code、
Codex 或 Auto。原生回合成功完成後，尚未命名的對話會沿用 Session 資訊中
**智慧命名**的流程，使用經過濾的首次請求與近期脈絡。命名助理會使用該帳號額度；Auto 在首次失敗時可改試
另一個助理，最多執行兩次小型模型回合。原本關閉的設定仍保持關閉；啟用 Gemini 本身不會
開啟自動命名或消耗命名額度。

名稱依確切對話保存在本機，daemon 重啟後仍保留。手動名稱與看板／任務名稱
優先。自動命名失敗或被中斷後，不會每回合或每次重啟都重試；需要重試時可
明確使用**智慧命名**。命名期間仍可傳送下一則 Gemini 訊息；若執行中關閉設定，
則不會套用產生的名稱。

Clawdline 不再限制只能開兩個 Gemini 對話。每個明確開啟的對話使用自己的原生
程序；開得越多，可能使用越多本機記憶體與 CPU。開啟操作仍依序執行，原生服務
與供應商的錯誤仍會回報。建立請求若指定模型，會先從該原生對話提供的模型中
選取，確認後才顯示 Session；不支援的選擇不會發布未設定好的 Clawdline Session；原生 CLI 仍可能保留建立過
的空白對話。在 Clawdline
管理的 Gemini Session 中，也可輸入 `/model <原生模型 ID>` 或
`/effort <提供的值>` 使用既有設定操作，這些不會作為模型提示送出。

## 助理傳送的圖片

使用 `clawdline image send` 發布的圖片，會沿用其他助理的圖片縮圖與原圖讀取
方式。舊 Gemini 回覆中的完整圖片 marker 也會轉成圖片；放在 fenced code
範例中的 marker 仍保留文字。原生回覆內容不會被改寫；過期或未知圖片維持
既有的無法讀取狀態。

指定 Session 傳送圖片時，會綁定同一份歷史世代中，接著出現的第一則助理
回覆。分頁與一般 daemon 重啟仍指向同一列，助理的文字不需要保留 marker。
歷史世代被替換後，不會拿舊列號綁到新的回覆。使用舊版僅回傳 marker 的 API
傳圖時，仍需在回覆中保留該 marker。
