# Bot 工作卡：給你看的摘要

狀態：提案第三版，等你審閱。還沒有實作任何東西。完整設計（英文）在
[`bot-work-cards.md`](bot-work-cards.md)。

這一版照你的意思簡化：不過度設計，保持彈性，等真的出問題再加。部署狀態由 Bot 自己回報，
系統不擋任何 commit 或部署，卡片可以像待辦一樣拆開、合併。前兩版寫過、這一版拿掉的機制，
列在最後的「先不做，需要時再加」。

## 要解決什麼

你把工作交給幾位常駐 Bot：開發、審查、測試，最後由整合的 Bot 合併、推送、裝開發版、部署。
這個月下來，同一件事的進度散在好幾個 Bot 的聊天裡：

- 想知道「這件事現在在誰手上、審過沒、交付到哪了」，得翻好幾個 Bot 的對話。
- 審查 Bot 退回了兩個 commit，它們還是上了遠端和 Cloud。退回只是一句聊天訊息，工作旁邊
  看不到這個結果。
- 到了 main、GitHub、開發版、Cloud 沒有，每次都靠人去看；完成後通知交辦的 Bot 也是靠記得。

## 跟現有「派工結果卡」的關係

Bot 聊天室裡已經有一張卡（最近剛上線），顯示**一次派工**的結果：那個 Session 交付的 commit、
目標分支、是否已落地，以及連結的看板項目的獨立驗證，還能點進去看那個 Session。

這份提案是另一層，而且建在它上面：

- **現有的卡**＝一個派出去的 Session 做出了什麼。
- **新的卡**＝你交代的**一件事**，跨好幾位 Bot：現在在誰手上、審查怎麼說、回報交付到哪了。
- 屬於同一件事的派工結果卡，會排在新卡底下當作執行細節，樣子不變。
- 新卡不另外定義「交付的 commit」「落地」這些事實，直接顯示派工結果卡已經有的那些。

## 它是什麼

獨立的一類紀錄：不是看板項目，不算進看板的數字，你自己建的看板項目和 Session 的用法都不變。

卡片記錄：

- **是誰授權的**：你哪一則訊息（或 Bot 轉達你的哪一則訊息）。
- **現在在誰手上**：開發、審查或整合，以及是哪一位 Bot。交接都留紀錄，不能改寫。
- **審查結果**：通過、有條件通過（寫明條件）、退回（寫明原因），都綁定確切的 commit。
  **只記錄、只顯示，不擋任何事。**
- **交付清單**：預設兩項，main 和 GitHub；開卡的 Bot 可以再加（例如開發版、Cloud、
  「上線後看過」）。手上拿著卡的 Bot 逐項打勾，附上版本或 commit。每一項都標明
  「某某 Bot 於某時回報」，系統不自己去查。
  唯一例外：派工結果卡如果已經有系統記錄的落地 commit，會顯示在 main 那一項旁邊供對照。

## 你會看到什麼

- **看板多一區「Bot 工作」，預設顯示**，可以依 Bot 篩選。每張卡有燈：建置、審查，
  加上交付清單的每一項。清單項目的綠燈代表「Bot 回報已完成」，滑過去看得到是誰、何時、
  備註；灰色代表不需要。審查燈：通過綠、有條件通過黃、退回紅。
- **需要你回答的卡放在這一區最上面**，同時出現在 Bot 聊天室和通知。**不會**出現在看板的
  「需要處理」欄。
- **Bot 聊天室**：同一件事的派工列和派工結果卡會排在一起，一行就看得到燈號。
- **手機和 Cloud 看到同一份資料**，內容一樣經過加密傳送。

## 拆開與合併

卡片像待辦一樣可以調整：

- **拆開**：一則訊息裡有好幾件事，可以把一張卡拆成幾張。新卡沿用同一則訊息的授權；
  已經派出去的工作留在原來那張，新卡從空的開始，並標明是從哪張拆出來的。
- **合併**：幾張卡其實是同一件事，可以併成一張。被併掉的卡不會刪除，只是關閉並指向留下的
  那張；它的紀錄、審查結果、派出的工作都會顯示在留下的那張底下。完成時，每一位交辦過的
  Bot 都會收到通知。
- **誰可以做**：你、當初接到交辦的 Bot、目前拿著卡的 Bot。
- 重試不會拆出或併出第二份。合併不能復原，要分開就再拆一次。

## 什麼時候算完成

交付清單每一項都打勾（或標成不需要）之後，拿著卡的 Bot 把卡片標成完成。系統**通知你，
也通知交辦的 Bot**，各一次，重開機或重試都不會重複。你隨時可以手動完成、取消或重開。

## 卡片從哪裡來

你交代 Bot 一件**會改到程式或文件**的事，Bot 第一次派出要寫檔的工作時，系統就自動開卡。
只是問問題、做調查不會開卡。同一則訊息不管經過幾位 Bot、重試幾次，都先只有一張卡；
要分成幾張就用拆開。

## 先不做，需要時再加

下面這些前兩版設計過，這一版刻意拿掉。其中「擋下被退回的 commit」是考慮過之後決定延後，
等問題再發生才做。

- 系統自己去讀各個去處的版本（含定時重讀）。
- 部署 Cloud 一定要有系統跑過的檢查結果。
- 偵測被退回的 commit 已經上線並警告。
- 推送、裝開發版、部署 Cloud 時擋下被退回的 commit。
- 認出被複製成新 commit 的退回內容。
- 由你放行被退回 commit 的專用操作。
- 「有條件通過」擋住任何動作。
- 固定的階段流程與每一步的檢查。
- 把「取代」「順便帶上」記成結構化的關係（目前寫在交接備註裡）。
- 一次整合好幾張卡的批次紀錄（目前可以合併卡片，或逐張打勾）。
- 證明複製或壓縮過的落地確實含有審查過的內容。
- 偵測交付後又被還原。
- 各專案自己定義去處（目前用清單項目代替）。
- 獨立的「上線後驗收」角色（目前用清單項目代替）。

## 刻意不做的

- 不幫你排誰來審查，也不替 Bot 跑建置、推送或部署。
- 不處理從別台電腦的 Bot 網路送來的請求。
- 不改動看板項目，也不放進看板的數字或「需要處理」欄。
- 看板項目上的「交給 Bot」按鈕：這是之後可能的一步，不在這份提案裡。將來要做的話兩者可以
  並存：你在項目上按下去就等於授權，卡片會連到那個項目；項目仍然是你的，Bot 不會去動它，
  卡片只記錄 Bot 這一側的進度。

## 已經照你的決定寫進去的

- 「Bot 工作」區預設顯示。
- 需要你的卡不放進看板的「需要處理」欄。
- 預設清單是 main 和 GitHub，其他由開卡的 Bot 加。
- 一則訊息可以有好幾張卡（拆開），也可以合併。
- 完成時也通知你。
- 不做任何強制；審查結果只顯示。

## 還需要你決定的事

1. **名稱**。最近上線的那張聊天室卡片，在 commit 標題裡已經叫「Bot work card」。兩樣東西
   需要兩個名字。建議：聊天室那張叫**派工結果卡（work result card）**，這份提案的新紀錄叫
   **Bot 交辦卡（Bot request card）**。這樣可以嗎，還是你想用別的名字？
第 2、3 題文件裡已先寫了預設（第 2 題：可以；第 3 題：同一個專案的卡都可以併），
你選另一邊也只是小改動。

2. 拿著卡的 Bot 可以自己把清單的某一項標成「不需要」（會顯示原因）嗎？還是只有你能拿掉項目？
3. 來自你**不同訊息**的卡可以合併成一張嗎？還是只有從同一則訊息拆出來的卡才能併回去？
