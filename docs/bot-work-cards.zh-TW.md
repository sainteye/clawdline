# Bot 工作卡：給你看的摘要

狀態：提案第四版，等你審閱。還沒有實作任何東西。完整設計（英文）在
[`bot-work-cards.md`](bot-work-cards.md)。

這一版只把你 2026-11-24 的三個決定寫進去，其他沒有多加：**非開發的任務也用這張卡**、
**流程比較長的任務才開卡**、**要不要開卡由 Bot 判斷，不確定就問你**。原則不變：不過度設計，
保持彈性，真的出問題再加。

## 它是什麼

你交代 Bot 的**一件事**，一張卡。這件事可能經過好幾位 Bot、花上好幾天，卡片讓你不用翻聊天
就知道：

- **是你哪一則訊息交代的。**
- **現在在哪一位 Bot 手上。** 交接都留紀錄。
- **做到哪一步了。** 卡片上有一份清單，Bot 做完一項就打勾，附上證據：可以是 commit、版本，
  也可以是一個網址或發布出去的成品。每一項都標明「某某 Bot 於某時回報」，系統不自己去查。
- **是不是在等你。**
- **完成了沒。** 完成時通知你，也通知當初交辦的 Bot。

它不是看板項目，不算進看板的數字；你自己的看板項目和 Session 用法都不變。卡片本身不會替 Bot
做事：不排程、不推送、不部署、不發文。

卡片**不要求一定跟程式有關**。沒有派工、沒有 commit、沒有審查結果的卡，一樣可以開、可以完成；
那些欄位沒有就不顯示。

## 哪些任務會有卡

**流程比較長的任務**：有好幾個步驟，通常跨好幾輪對話，中間常要等另一位 Bot 或等你。

- 開發：做一個功能、修一個 bug。
- 發布：草稿 → 審稿 → 發布。

問一個問題、查一個資料、一次回覆就做完的事，不開卡。

**由 Bot 自己判斷要不要開卡；不確定就問你**（聊天裡簡短問一句）。你可以直接用講的調整它的
習慣，例如「發版公告一律開卡」「改錯字不用開」，Bot 會記在自己的常駐指示或記憶裡。沒有另外的
設定頁或規則表。

同一則訊息不管經過幾位 Bot、重試幾次，都只會有一張卡；要分成幾張就用「拆開」。

前一版寫的「Bot 第一次派出要寫檔的工作時，系統自動開卡」**這一版拿掉了**，也不留著當備援。
原因：它只認得派工，非開發的任務根本碰不到；留著的話會變成兩邊都能開卡，系統還會替 Bot
判斷為不需要的小事開卡，等於推翻你交給 Bot 的判斷。

## 兩個例子

**做一個功能。** 你請主責的 Bot 加一個功能。它開一張卡，清單預設兩項：main、GitHub（它可以再加
「開發版」「Cloud」）。它派工、寫完後把卡交給審查的 Bot；審查結果（通過、有條件通過、退回）
記在卡上，綁定確切的 commit，**只記錄、只顯示，不擋任何事**。接著交給整合的 Bot，合併、推送
後逐項打勾並附上 commit。全部打勾後標成完成，你和主責的 Bot 各收到一次通知。原本聊天室裡每次
派工的「派工結果卡」照舊，排在這張卡底下當作執行細節。

**在社群頻道發一則貼文。** 你請 Bot 寫一則本週更新的貼文並發出去。它開一張卡，清單預設三項：
草稿、你審過、已發布。

1. Bot 寫好草稿，勾「草稿」，然後問你要不要這樣發。
2. 這張卡進到「**等你回覆**」，排在 Bot 工作區最上面，直到你回答。
3. 你在 Bot 聊天室回覆。Bot 勾「你審過」；你要求修改的話，它先改再勾。
4. Bot 發出貼文，勾「已發布」，**貼文連結就是證據**。
5. 三項都勾完，卡片完成，你收到通知。

這張卡沒有派工、沒有 commit、沒有審查結果，所以不顯示建置燈和審查燈。

## 你會看到什麼

- **看板多一區「Bot 工作」，預設顯示**，可以依 Bot 篩選。開發和非開發的卡都在這一區；它們
  不是看板項目，不算進看板的數字。
- **每張卡一排燈**：清單每一項一顆（空＝還沒、綠＝Bot 回報完成、灰＝不需要），滑過去看得到
  是誰、何時、備註，備註是網址的話可以點。有派工才多一顆建置燈，有審查結果才多一顆審查燈
  （通過綠、有條件通過黃、退回紅）。
- **等你回覆的卡排在這一區最上面**，同時出現在 Bot 聊天室和通知。**不會**出現在看板的
  「需要處理」欄。
- **Bot 聊天室**：同一件事的派工和派工結果卡會排在一起，一行看得到燈號。
- **手機和 Cloud 看到同一份資料**，內容一樣經過加密傳送。
- **拆開與合併**：卡片像待辦一樣，一張可以拆成幾張，幾張可以併成一張。你、當初接到交辦的
  Bot、目前拿著卡的 Bot 都可以做。被併掉的卡不會刪除，紀錄會顯示在留下的那張底下。

## 刻意保持簡單的地方

- **只有一種卡。** 開發和非開發的差別只在開卡時預設的那份清單；清單項目是自由文字，Bot 可以
  自己寫。
- **非開發任務不另外設計**：不做各頻道的串接、不做專門的核准流程（Bot 問你、你回答就是審稿）、
  不做清單以外的範本。
- **狀態都是 Bot 回報的**，系統不去讀版本、不檢查連結是不是真的上線。
- **不做任何強制**：審查結果只顯示，不擋推送或部署；沒有固定的階段流程。
- **開卡靠 Bot 判斷**，沒有自動開卡。如果之後發現 Bot 常忘記開，先在它的常駐指示補一句，
  還不夠再加提醒，最後才考慮讓系統自動開。
- 前幾版設計過、現在都延後的機制（系統自己查交付狀態、擋下被退回的 commit、批次整合紀錄等），
  完整清單在英文版第 13 節。

## 還需要你決定的事

1. **名稱**。最近上線的那張聊天室卡片，在 commit 標題裡已經叫「Bot work card」。兩樣東西
   需要兩個名字。建議：聊天室那張叫**派工結果卡（work result card）**，這份提案的新紀錄叫
   **Bot 交辦卡（Bot request card）**。這樣可以嗎，還是你想用別的名字？
   （已對照非開發任務：「交辦」只表示你交代了一件事，貼文和功能都適用；「派工結果」只用在
   有派工的聊天室卡片，也仍然正確。）

第 2、3 題文件裡已先寫了預設（第 2 題：可以；第 3 題：同一個專案的卡都可以併），
你選另一邊也只是小改動。

2. 拿著卡的 Bot 可以自己把清單的某一項標成「不需要」（會顯示原因）嗎？還是只有你能拿掉項目？
3. 來自你**不同訊息**的卡可以合併成一張嗎？還是只有從同一則訊息拆出來的卡才能併回去？
